Subscription Synchronization
Apply provider-neutral commercial access snapshots from the authenticated Connect service.

Connect owns vendor credentials, webhook processing, canonical API reads, entitlement mapping, retries, customer-link discovery and five-minute reconciliation. Core does not call a billing provider. The internal controller is excluded from public Swagger; the offline internal artifact generates the SDK client consumed by Connect.

The service API prepares a per-organization revision before Connect reads provider state. Applying a normalized subscription, Academy flag and opaque external owner acquires the revision row and seat allocation lock before changing local state. The wait for the revision row is bounded by a five-second `lock_timeout` that stays in force for later lock waits in the same transaction; statement execution keeps the configured statement timeout. A superseded revision returns 409. Connect retries webhook deliveries; its periodic sweep skips superseded work without treating the race as a provider failure. Successful applications rotate the revision, including no-op replays. Cleanup observes without rotating and may revoke only its exact current owner. Core validates organization existence, dates, access model and allowances; provider event payloads never bypass these checks.

Subscription application owns the seat allocation lock. It joins the outer transaction, so the lock remains held through free-trial, Academy, ownership and event writes; independent subscription callers acquire the same lock.

Subscription, free-trial, Academy, ownership and pending outbound events commit in one transaction. Pending events form a name/payload union of the existing domain events, and webhook mapping exhaustively handles that union. Only actually active subscriptions exhaust a free trial. Local listeners execute inside that transaction; outbound Core webhooks use the durable ordered outbox and bounded retry leases. External delivery failure cannot roll back committed local access or replay local effects.

Ownership, revisions, ordered outgoing events and reconciliation leases use the `subscription_sync_links`, `subscription_sync_revisions`, `subscription_sync_outbox` and `subscription_sync_leases` tables. Owner IDs are opaque to Core. The lease table uses database time and worker tokens to coordinate reconciliation in Connect; expired workers cannot release a replacement worker's lease.

`FEATURE_EXTERNAL_SUBSCRIPTIONS_ENABLED` defaults off and is cloud-only. Disabled/self-hosted deployments reject prepare, apply and coordination requests. Committed outgoing work can still drain after disabling writes. Core requires only the Connect service credential; all provider credentials belong in Connect.

Validation includes strict HTTP DTO checks with independent user/service principals, real-record PostgreSQL lifecycle/rollback/lease tests, the actual generated SDK contract and public-schema exclusion checks. No UI or provider network is required by this module's tests.

After the transaction returns successfully, the application audit records organization, revision/delivery IDs, requested/previous/next opaque owners, access type and allowance, Academy, revoke, changed and outcome. An ownership-mismatched revocation is explicitly logged as skipped. Failed/rolled-back work never produces the committed-state log; billing fields and credentials are excluded.

Ordered delivery policy: retries have no automatic discard, retry-exhaustion, skip or dead-letter path. A malformed or unsupported record and an unavailable receiver both retain the oldest event and block later events for that organization; other organizations can continue. Delivery retries are delayed by 60 seconds, while abandoned claims recover after their two-minute lease. Corrupt V8 bytes are returned with their claim identity and rejected by delivery validation, not lost inside claiming. Error logs identify organization, event ID, age and a safe failure code without payload data. Operational alerts can use these fields; configuring production alerts is separate from this implementation.

Recovery preserves the existing event ID and ordering: repair the receiver or deploy a compatible reader, then allow the next retry. Stored event names are compatibility contracts, independent of TypeScript class renames. The captured pre-cleanup binary fixtures test that queued records remain readable. A corrupt payload requires restoration from verified data through an explicitly reviewed repair; it must not be guessed, deleted or bypassed automatically. There is no public queue-editing endpoint. The trade-off is intentional: an unresolved record can hold its organization's deliveries indefinitely and needs operator attention; automatic skipping would change the delivery guarantee.
