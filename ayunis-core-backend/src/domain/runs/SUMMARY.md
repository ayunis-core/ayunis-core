AI Execution
Orchestrate AI inference runs with streaming message responses

Runs execute AI conversations by coordinating model inference, message creation, tool execution, and response streaming. Each run processes user or tool-result input within a thread context.

The runs module is the central orchestrator for AI conversation execution. The `Run` entity (currently minimal) represents an execution instance, while `RunInput` differentiates between `RunUserInput` (text and images) and `RunToolResultInput` (tool call responses). The primary use case `ExecuteRun` resolves the thread, agent, and model, then delegates pre-inference resource gating to `InferenceUsageGuard.preflight` (after `pickModel`, before `orchestrateRun`, so the tier bucket matches the resolved model — untiered models default to MEDIUM, while ZERO-tier models bypass the fair-use check). The guard combines the fair-use quota check (`CheckQuotaUseCase` via `tierToFairUseQuotaType`) and the org-scoped credit-budget check (`CreditBudgetGuardService`) into a single entrypoint that is also reused by the OpenAI-compat surface. Credit-budget and credit-limit gating is skipped for models that do not consume credits (`LanguageModel.consumesCredits === false` — free open-source models with no configured token costs, e.g. German-hosted "DE" models), so they stay usable after the org's monthly credit budget is exhausted; the fair-use quota still applies to them. The iteration loop is delegated to focused services. `ExecuteRunAndSetTitle` extends this to auto-generate thread titles on first messages. `SendMessage` is the endpoint-level use case behind `POST /runs/send-message`: it consumes a trial message when the command asks for it (fire-and-forget with a caught, logged failure; orgId from `ContextService`) and delegates to `ExecuteRunAndSetTitle`.

The HTTP layer (`presenters/http/`) is split into focused units: `RunsController` (thin endpoint — cross-field validation, command construction, delegation), `SendMessageRequestValidator` (multipart rules DTO decorators cannot express), `RunEventResponseMapper` (run event → response DTO), and `RunSsePresenter` (owns the SSE transport: headers, event framing, heartbeat, disconnect/error tracking, and teardown — every write path is guarded because it runs outside NestJS exception filters). Run error events use `ApplicationError.toClientResponse()`: expected 4xx metadata such as quota `retryAfterSeconds` remains available to clients, while 5xx messages and metadata stay server-side.

### Services

- **RunTelemetryService** — Records the existing attempted-run activity signal and wraps the selected execution stream so each run emits exactly one low-cardinality terminal outcome and end-to-end duration, including preparation errors and consumer abandonment.
- **ToolAssemblyService** — Assembles available tools and builds the run context (system prompt instructions) from thread, agent, active skills, project workspace context, always-on skill templates, and model capabilities. Project-assigned skills contribute always-on instructions/resources but are excluded from `activate_skill` choices. Builds a unified slug map (`user__<slug>` for user skills, `system__<slug>` for always-on templates) that is passed to both the system prompt builder and the `ActivateSkillTool` entity. Artifact tool assembly (documents, diagrams, spreadsheets) is delegated to `ArtifactToolAssemblerService`. The `assembleImageGenerationTool()` method conditionally includes the `generate_image` tool when an image-generation model is effectively available to the current user (checked via `GetPermittedImageGenerationModelUseCase`, which is team-override aware — members of teams with overrides enabled only get the tool if the image model is assigned to one of their teams); otherwise the tool is omitted from the run context. The `assembleInternetTools()` method gates the `website_content` and `internet_search` tools behind the org chat settings (`GetOrgChatSettingsUseCase`, chat-settings module): when an org admin has disabled internet access, neither tool is offered; web search additionally requires the provider to be configured (`internetSearch.isAvailable`).
- **ArtifactToolAssemblerService** — Assembles the artifact tools for a run (create/update/edit document, create/update diagram, create/update spreadsheet; extracted from `ToolAssemblyService` to keep that file under the size cap). Enriches each update tool's description with the thread's matching artifact IDs and titles — spreadsheets additionally carry `(current version N)` so the model always has a fresh `expected_version` even after user edits in the grid — and appends org-scoped letterhead IDs to the document tools.
- **McpToolAssemblerService** — Discovers and assembles MCP tools and resources for a thread's integrations (extracted from `ToolAssemblyService` to keep that file under the size cap). Tolerates unavailable integrations (`Promise.allSettled`, warn and skip) and filters duplicate tool names: MCP tools assemble last with built-in names reserved, so a third-party tool can never shadow a built-in, and later duplicates are dropped with a warning. Tool names stay canonical end-to-end here — wire-safe renaming is the provider packages' concern (`ToolNameCodec` in `packages/inference`).
- **ToolResultCollectorService** — Settles tool phases for the feature-toggle legacy loop using the same concrete host policy as runtime tool assembly: charts acknowledge without backend execution and continue, externally handled email/calendar/skill widgets terminate, backend tools expose their results, and hybrid artifact tools execute once but expose the display acknowledgement. The legacy loop settles every sibling before terminal completion and never collects stale calls before a new user message. Client-rendered tool params are validated before acknowledgement or handoff, while explicit frontend-supplied results bypass historical validation. The service also anonymizes PII results, truncates oversized output, and returns per-result `outcomes` for the repeated-failure breaker (AYC-646, AYC-675, AYC-704).
- **InferenceOrchestratorService** — Coordinates the full inference flow: trims thread messages to fit the context window, delegates to `StreamingInferenceService` or `NonStreamingInferenceService` based on the streaming flag, collects usage, and adds the assistant message to the thread. Wraps non-`ApplicationError` failures in `RunExecutionFailedError`.
- **StreamingInferenceService** — Executes streaming inference, accumulates response chunks into partial `AssistantMessage` updates, and persists the final result. Records usage from streaming chunks via `InferenceUsageGuard.collectUsage`. A completed stream whose tool-call arguments don't parse — or that hit the token limit while emitting a tool call — fails with `InferenceFailedError` and persists none of the turn's tool calls (`tool-call-arguments.helper.ts`): executing a guessed `{}` input fails schema validation identically on every retry (AYC-646). Truncated text-only answers are still saved. If final persistence discovers that the thread was concurrently deleted, both run implementations end with the existing aborted outcome before any streamed tool calls execute.
- **NonStreamingInferenceService** — Executes non-streaming inference with metrics instrumentation. Emits `InferenceCompletedEvent` with timing and error info.
- **InferenceUsageGuard** — Single entrypoint for pre-inference resource gating (`preflight`) and post-inference usage recording (`collectUsage`). Combines `CheckQuotaUseCase` (user-scoped fair-use, skipped for api-key principals), `CreditBudgetGuardService` (org-scoped credit budget) and `CreditLimitGuardService` (user/team credit limits) — both skipped when `model.consumesCredits` is false so free open-source models remain available after the budget is exhausted — and `CollectUsageAsyncService` (re-exported from the usage module). Extracted from `ExecuteRunUseCase` so the OpenAI-compat surface can reuse it without duplicating logic. Exported from `RunsModule` for use by other modules.
- **CreditBudgetGuardService** — Orchestrates a pre-run credit-budget check by combining `GetMonthlyCreditLimitUseCase` (from subscriptions) and `GetMonthlyCreditUsageUseCase` (from usage). Throws `CreditBudgetExceededError` when the organization's monthly credit limit is reached. Lives in the runs module because it is the run execution flow that needs this cross-domain decision. Consumed by `InferenceUsageGuard`.
- **MessageCleanupService** — Cleans up threads after a failed or interrupted run by rolling the incomplete turn back to the most recent assistant response without tool calls. Called on error and aborted paths — successful runs leave the thread in a valid state by design. `RunToolRepeatedlyFailingError` skips cleanup in both run loops — the breaker fires only after its tool-result transcript is persisted, and rolling that back would re-arm the turn's pending tool calls. The runtime loop also skips cleanup for `RunMaxIterationsReachedError` (its final tool phase completed); the legacy loop does not, because there max-iterations ends after inference with an unexecuted tool phase that must be rolled back.
- **SystemPromptBuilderService** — Builds system prompts from agent configuration, thread context, active skills, and project context. Accepts `SkillEntry[]` (slug + description) instead of `Skill[]` for activatable skills — the slug is used as the skill name in the prompt — plus `projectInstruction` and `projectSkills` for always-on workspace context.

### Helpers

- **resolve-integration.helper.ts** — Pure functions for resolving MCP integration metadata. `resolveIntegration` matches tool names to `McpIntegrationTool` and `McpIntegrationResource` instances and extracts integration metadata. `enrichContentWithIntegration` attaches integration metadata to `ToolUseMessageContent` blocks in assistant responses.
- **append-skill-activated-note.ts** — Preserves the quick-action skill marker when runtime context is rebuilt after a later `activate_skill` call.
- **skill-slug.ts** — Located in `src/common/util/`. Pure functions for slugifying skill names (`slugify` with German transliteration), building prefixed slugs (`buildSkillSlug`), parsing slugs back to prefix + slug (`parseSkillSlug`), and building collision-safe slug→name maps (`buildSlugMap`). Defines `SYSTEM_PREFIX` (`system`) and `USER_PREFIX` (`user`) constants.

### Agent runtime adapters

The `application/agent-runtime/` directory backs the feature-toggle-selected runtime execution path. `inference-message.mapper.ts` maps provider-agnostic inference messages back to backend assistant and tool-result messages, `run-event-stream.adapter.ts` folds runtime-owned, accumulated tool-call snapshots into the existing `RunStreamItem` stream while preserving the terminal `completed` or `aborted` outcome, and `masks-event.ts` defines the custom event name used for PII-mask updates. Streaming snapshots expose raw arguments and best-effort input to the client without parsing provider fragments again; a terminal invalid snapshot (or a token-limit finish while tool calls were being emitted) fails the model call with `MALFORMED_TOOL_CALL`, mapped to `InferenceFailedError` — the turn's intact text still reaches the interrupted-persistence phase, but no tool call from a corrupted turn is ever executed with guessed input (AYC-646). Every durably persisted runtime message is passed through `AddMessageToThreadUseCase`, preserving the legacy `ThreadMessageAddedEvent` and activity semantics. An aborted outcome triggers orphan-message cleanup and suppresses first-run title generation without becoming a client error frame. `RuntimeModelProviderDecorator` is the host-side boundary around the transformed provider returned by `ResolveModelProviderUseCase`: every SDK model call sanitizes replayed tool inputs, relays client cancellation, applies the shared inter-chunk stall watchdog (`STREAM_IDLE_TIMEOUT_MS`), maps provider/oversized-image/unknown failures to the established backend taxonomy, records privacy-safe diagnostics for provider request rejections, and emits exactly one `InferenceCompletedEvent`. The adapter reconstructs classified runtime errors so their codes, HTTP status, metadata, and AppSignal grouping survive the package boundary. Runtime hooks persist messages, collect model and tool usage, and rebuild the available tools and instructions after `activate_skill`; `SkillActivationHookFactory` preserves any quick-action skill marker while refreshing that context. Interrupted model calls expose their accumulated text and thinking through a dedicated lifecycle phase, allowing the persistence hook to save a deterministic partial assistant turn without unexecuted tool calls or empty messages. Grouped tool results are durably flushed by the final `afterToolCall` hook before their message event is exposed. Critical finalization failures are logged with hook attribution and override the host-facing error while retaining the runtime's original terminal status; if the last result flush fails, cleanup rolls the incomplete turn back to the previous completed assistant response. `RuntimeHistoryMaterializer` selects the newest complete backend turns before inference mapping downloads image bytes, while `ContextBudgetHookFactory` reapplies the same selection before every model call after tool results grow the in-memory history. Both delegate to `CompleteTurnSelector`, which uses `TokenCounterModule`; neither mutates the persisted transcript. Runtime iteration caps count complete model-and-tool iterations, so a final tool phase remains persisted when the run ends with `max_iterations`; the runtime's `TOOL_REPEATEDLY_FAILING` breaker error (mapped to `RunToolRepeatedlyFailingError`) preserves its final tool phase the same way. The backend declares `@ayunis/agent-runtime` as a workspace dependency and builds it with the other inference packages.

`BackendToolAdapter` is the single runtime-facing tool assembly boundary. Every assembled tool has optional `validateInput` and `execute` callbacks: charts validate and return a successful display acknowledgement without invoking `ExecuteToolUseCase`; email, calendar, and create/edit skill widgets validate but omit `execute`, making their settled tool phase terminal; backend tools delegate exactly once and expose their normal result; hybrid artifact tools delegate exactly once and replace successful raw output with the display acknowledgement. The generic runtime knows only that missing `execute` means external handling and contains no Ayunis tool names or UI concepts. Mixed phases settle every sibling before continuation or termination, and invalid external input remains model-actionable and retryable (AYC-675, AYC-704).

`RunSsePresenter` creates the run event source with an `AbortSignal`. Response close, socket error, and failed heartbeat writes abort it immediately; the optional signal is propagated through the run commands and passed to `@ayunis/agent-runtime` only on the feature-enabled SDK path. Normal completion does not synthesize a cancellation, and the feature-disabled legacy path remains behaviorally unchanged.

Note: **SkillActivationService** (which handles copying skill sources, MCP integrations, and returning instructions to the thread) lives in the **skills module** (`src/domain/skills/application/services/skill-activation.service.ts`) and is consumed by both the runs module (`ExecuteRunUseCase`) and the tools module (`ActivateSkillToolHandler`).

Domain events are defined in `application/events/`: `RunExecutedEvent` retains the user/org-scoped activity signal; `RunTerminalEvent` emits exactly once per selected run path with the bounded `legacy` / `agent_runtime` path, terminal outcome, and end-to-end duration; `InferenceCompletedEvent` includes the explicitly supplied execution path alongside model, provider, streaming flag, duration, and optional error; `RunToolCompletedEvent` captures low-cardinality success/error/aborted outcomes without identifiers; and `ToolUsedEvent` retains detailed tool and MCP integration identity for existing analytics/webhooks. `RunTelemetryService` wraps the selected generator so preparation failures, normal completion, aborts, max-iteration errors, and abandoned client streams share one terminal measurement. Each event class exposes a static `EVENT_NAME` string for type-safe listener registration. Usage persistence emits `RunUsageCollectionEvent` with an optional run execution path from the **usage** module; OpenAI-compatible and image-only usage omit it rather than inventing a third path value.

The module integrates with **threads** for conversation context, **messages** for creating and reading conversation history, **models** for inference routing, **tools** for executing tool calls during runs, **agents** for loading agent configurations, **skills** for on-demand skill activation and source/MCP injection, **mcp** for fetching integration metadata (`GetMcpIntegrationsByIdsUseCase`, `MarketplaceMcpIntegration`), **usage** for tracking token consumption, **chat-settings** for org-wide and user-level system prompt injection (`GetOrgSystemPromptUseCase`, `GetUserSystemPromptUseCase`), **artifacts** for discovering thread artifacts during tool assembly, **workspaces** for project context (`BuildWorkspaceRunContextUseCase`), **letterheads** for listing org-scoped letterheads that can be attached to document tools, **subscriptions** for credit budget enforcement (`GetMonthlyCreditLimitUseCase`, with `CreditBudgetExceededError` re-exported from `runs.errors.ts` for backward compatibility), and **quotas** for applicable tier-aware fair-use enforcement via `CheckQuotaUseCase` before model inference.
