Audio Transcription
Speech-to-text transcription via external provider APIs

Transcriptions convert uploaded audio files into text using external transcription services. The module exposes an HTTP endpoint for file upload and returns transcribed text content.

The module provides two application workflows through `TranscriptionPort`, implemented by `MistralTranscriptionService`. `TranscribeUseCase` serves browser microphone uploads and returns plain text. `TranscribeRecordingUseCase` prepares uploaded source recordings, transcribes their parts and returns text with original timestamps for the retrieval pipeline. The module exports both use cases and the provider port. Its controller serves the microphone workflow; source recordings enter through the retrievers module.

Audio remains transient within this module; the sources module owns original files and saved processing results. Error handling covers unsupported formats, provider failures and file size limits.

Uploaded source recordings use the separate `TranscribeRecordingUseCase`, leaving browser microphone behavior unchanged. `FfmpegAudioSegmenterAdapter` inspects duration (bounded decoding when WebM metadata omits it), sends the original whole when it fits verified duration/byte budgets, compresses an oversized whole recording to mono 16 kHz / 32 kbit/s MP3 when possible, and otherwise emits valid time/byte-bounded MP3 parts and removes temporary files after each part and attempt. Supported demuxers and file/pipe protocols are explicit; MOV external references are disabled. `MistralTranscriptionService.transcribeSegment` requests diarization and segment timestamps with a separate configurable five-minute timeout; the tested default model is pinned to `voxtral-mini-2602`. Saved per-part results are reused on retry; timestamps are offset into the original recording and retained in the searchable text. Speaker turns are sorted without dropping overlaps, labelled per request, and scoped to the part when splitting is needed. Missing speaker IDs retain timestamped text; missing segments retain plain text. Provider labels are not a guarantee of real-person attribution. Checkpoint identity includes the new diarized result version. Concurrency and segment budgets come from `transcription.config.ts`; current public upload size remains 25 MiB. FFmpeg and ffprobe are required in the runtime image. Uploaded recordings have their own size cap (`AUDIO_MAX_UPLOAD_BYTES`, applied when the upload session is reserved and again by the use case); dictation keeps the 25 MiB constant. The segment budget is no longer tied to that constant: a budget that holds `AUDIO_MAX_DURATION_SECONDS` at 32 kbit/s (about 43 MiB for 3 h) sends every recording to the provider in one request, which keeps speaker labels consistent, since the provider only guarantees them within one transcript. A recording over the duration cap, or one the provider refuses as too large (413, or the context-length 400), fails with `RecordingTooLongError` (422, `RECORDING_TOO_LONG`): deterministic, not retried, shown to the user as a request to cut the recording.
