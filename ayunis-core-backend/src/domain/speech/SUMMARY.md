Speech
Read assistant messages aloud through Mistral text-to-speech

The speech module turns text the client has already prepared for listening into MP3 audio and streams it back while it is generated, so playback starts on the first chunk. Nothing is persisted: the client caches the audio of recently read messages itself.

`POST /speech` (`SpeechController`) takes the text and the user's UI language. It exists only while `readAloudEnabled` is on — `FEATURE_READ_ALOUD_ENABLED=true` plus a configured `MISTRAL_API_KEY`, the same key voice input needs; opt-in because the TTS model is a Mistral preview model whose inputs Mistral may train on — and, like the other chat surfaces, sits behind the academy-certificate gate. `SynthesizeSpeechUseCase` picks the language with `SpeechLanguageDetectorService` and hands the text to the `SpeechPort`. Mistral TTS has no language parameter; the language comes from the voice, so the detector decides which voice reads the text. It runs `franc-all` restricted to the languages with a preset voice plus those Mistral speaks without one, and falls back to the UI language when the text is shorter than 30 characters, the two best guesses are nearly tied, or the language has no preset voice (`domain/speech-language.ts`).

`MistralSpeechService` calls `POST /v1/audio/speech` with `stream: true` (model from `MISTRAL_TTS_MODEL`, default `voxtral-mini-tts-3-0`; `MISTRAL_SPEECH_SERVER_URL` points it at the e2e contract server), maps the language to one preset voice per language (`infrastructure/mistral-preset-voices.ts`) and decodes the base64 audio deltas. The use case resolves only after the provider accepted the request, so a rejection still reaches the client as an error status; a stream that breaks off later ends the response early. A disconnecting client aborts the provider request.
