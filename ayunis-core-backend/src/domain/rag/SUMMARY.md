Knowledge Pipeline
Retrieval-augmented generation with text splitting and vector indexing

RAG provides the ingestion pipeline for enhancing AI context: splitting documents into chunks via configurable splitters, then indexing those chunks with embeddings for semantic search and retrieval.

`EmbedTextUseCase` (`embeddings/application/use-cases/embed-text`) is the error choke point for embeddings provider failures: `ApplicationError` passes through, transport failures and upstream 5xx become the shared `ProviderUnavailableError` family via `wrapProviderFailure` from `src/common/errors` (stable AppSignal grouping per provider+failure-class, AYC-538), and unrecognized errors rethrow raw so internal bugs stay distinct. When `MOCK_INFERENCE=true`, embedding requests use deterministic local vectors while provider availability still reflects configured credentials.

The RAG module is organized into two sub-modules: **splitters** and **indexers**. Splitters handle text chunking with pluggable strategies (recursive and line-based), producing `SplitResult` entities from raw text via a handler registry. Indexers manage vector-based content storage using a parent-child index architecture where documents are split into parent and child chunks with embeddings for semantic search. Key entities include `IndexEntry`, `ParentChunk`, and `ChildChunk`. Use cases cover content ingestion, deletion, and semantic search. Ingestion is two-phase so re-indexing never loses the previous index: `PrepareBulkContentUseCase` splits and embeds a document's chunks into an indexer-specific `PreparedIndexContent` without writing anything (no transaction is held during provider calls), and `ReplaceBulkContentUseCase` deletes the document's existing entries and inserts the prepared ones in one transaction, joining the caller's transaction when one is active (`ParentChildIndexerRepository` reads and writes through the CLS `TransactionHost`). The `parent_chunks.relatedDocumentId` FK to `sources` cascades on source deletion, so parent/child chunks are removed automatically when their source is deleted. The indexer infrastructure uses PostgreSQL with pgvector for embedding storage. The module integrates with **models** for embedding model access, **sources** for document content to ingest, **retrievers** for content extraction before indexing, and **tools** (source_query tool) for runtime semantic search during conversations.
