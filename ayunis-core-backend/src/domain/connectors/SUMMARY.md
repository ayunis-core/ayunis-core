# Connectors Module

Connects an organization to an external product, such as Microsoft 365, so that other features can read from it on the organization's behalf. The module owns one connector per organization and product, its setup, its encrypted credentials and the product-specific clients (Microsoft 365: SharePoint through Microsoft Graph). Other modules get listings and file contents through its exported use cases; tokens and credentials never leave it.

Everything here is behind the `connectorsEnabled` feature flag (`FEATURE_CONNECTORS_ENABLED`, off by default).

## Domain

- **`Connector`** — `id`, `orgId`, `product`, `setup` (non-secret, product-specific values such as a tenant ID; `{}` when none) and `encryptedCredentials` (the product's secrets encrypted as one value, `null` when there are none). Unique per (`orgId`, `product`). A connector is **set up** while it has credentials, otherwise **not set up**: removing a connection clears its credentials but keeps the connector, so whatever references it reconnects when it is set up again.
- **`ConnectorProduct`** — `microsoft_365`.
- **`ConnectorStatus`** — `set_up`, `not_set_up`.
- **`ConnectorItem`** (`domain/sync/`) — a file below a synced location as a provider lists it: `id` (stable across renames and moves), `path` below the location, `name`, `version` (changes with the content), `size` and an optional `unprocessableReason` (`unsupported_type`, `too_large`, `encrypted`) the provider already knows.
- **SharePoint** (`domain/microsoft-365/`) — `parseSharePointUrl`: a URL copied from SharePoint Online (`*.sharepoint.com`) as host, site path (`sites/…` or `teams/…`, `''` for the root site) and the decoded path below it (library, folders); library views (`…/Forms/AllItems.aspx`, also with the folder in `?id=`), site pages (`SitePages`, `_layouts`) and `/:f:/r/…` links are understood, sharing links (`/:f:/s/…`) are not, as they only resolve through `/shares`. `siteGrant` / `folderGrant`: the Microsoft Graph PowerShell command (`Connect-MgGraph -Scopes "Sites.FullControl.All"`, then `Invoke-MgGraphRequest -Method POST`) that grants the organization's app `read` on a site (`POST /sites/{host}:/{site-path}:/permissions`, `grantedToIdentities`) or on a folder (`POST /drives/{drive-id}/root:/{path}:/permissions`, `grantedToV2`, for `Files.SelectedOperations.Selected`); values are PowerShell literal strings. `isProtectedOfficeFile`: a Word, Excel or PowerPoint download (by its content type) that is a compound file, i.e. encrypted (a Purview sensitivity label with encryption).
- **Microsoft 365** (`domain/microsoft-365/`) — the organization's own Entra app: setup `{ tenantId, clientId }` (GUIDs, `GUID_PATTERN`) and credentials `{ clientSecret }`. Client secret only; no certificates. `MICROSOFT_365_PERMISSIONS` lists the Microsoft Graph application permissions Ayunis uses: `Sites.Selected` (required), `Files.SelectedOperations.Selected` and `Lists.SelectedOperations.Selected` (optional). `Microsoft365ConnectionTestOutcome` is the result of a connection test: `connected` or the setup mistake that stops it (`tenant_not_found`, `client_not_found`, `client_secret_invalid`, `client_secret_expired`, `consent_missing`, `consent_on_wrong_api`, `required_permission_missing`, `rejected` for any other refusal, `microsoft_unavailable`).

## Ports

- **`ConnectorsRepository`** — `findAllByOrgId`, `findById`, `findByOrgIdAndProduct`, `upsert` (one `INSERT … ON CONFLICT (orgId, product)`, so the connector keeps its ID), `updateSetupOfSetUp` (one `UPDATE … WHERE "encryptedCredentials" IS NOT NULL`, so a concurrent removal cannot leave a setup without credentials) and `clearSetupAndCredentials`
- **`ConnectorCredentialEncryptionPort`** — `encrypt` / `decrypt` for credentials at rest
- **`ConnectorSyncAdapter`** — how one product syncs a location: `listChanges(connector, location, cursor)` and `fetchContent(connector, location, itemId)`, returning the outcomes in `application/models/connector-sync-results.ts`. `ConnectorSyncAdapterRegistry` holds one adapter per product: Microsoft 365's is `SharePointSyncAdapter`.
- **`MicrosoftGraphPort`** — Microsoft Graph v1.0 with an app-only token: `get(token, pathOrLink)` (a path below `/v1.0` or a link Graph returned) and `download(token, path)` (content, size, content type). Answers `ok`, `not_found`, `access_denied` (403), `resync_required` (410), `throttled` (`429`/`503` with `Retry-After`, as `retryAt`) or `rejected` (any other 4xx, with Graph's error code); throws a `ProviderUnavailableError` for transport failures, timeouts, 5xx and a 429 without `Retry-After`.
- **`EntraAppTokenPort`** — `requestToken(credentials, resource)`: an app-only token (client credentials flow) for Microsoft Graph or SharePoint, with the application permissions (`roles` claim) granted in it, or Entra's refusal (`EntraTokenRejection` plus its `AADSTS…` code). Throws a `ProviderUnavailableError` when Entra cannot be reached, times out or answers 5xx/429.

## Application Services

- **`Microsoft365AppTokenService`** — `requestToken(connector, resource)`: decrypts the connector's stored secret and requests an app-only token. Tokens and the secret stay inside the module; SharePoint ingestion reuses this service. `ConnectorNotSetUpError` while the connector has no credentials.
- **`Microsoft365ConnectionTestService`** — `test(connector)`: requests a Graph token and compares its roles with `MICROSOFT_365_PERMISSIONS`. A Graph token without roles is followed by a SharePoint token, which tells missing admin consent (`consent_missing`) from permissions added on the SharePoint API instead of Microsoft Graph (`consent_on_wrong_api`). Entra being unavailable is the outcome `microsoft_unavailable`; the failure is still reported to AppSignal (`reportUnexpectedError`). It does not read the app registration, which would need `Application.Read.All`. Returns `Microsoft365ConnectionTestResult`: outcome, the permissions Ayunis uses with whether each is granted, other granted Graph permissions, Entra's error code; never the token.

- **`Microsoft365GraphTokensService`** — Graph tokens for syncing, kept per connector until five minutes before they expire, so a sync asks Entra once rather than per file; changed setup or credentials get a new one. `withAccessToken(connector, work)` runs `work` with it, `null` while the connector is not set up or Entra rejects it; a token Graph refused (401) is dropped, for syncing and resolving alike.
- **SharePoint** (`services/sharepoint/`):
  - `SharePointLocationResolver` — resolves a parsed URL part by part, never through `/shares` (which answers 403 for granted-but-missing, not granted and non-existent alike): the site by path (403 → `not_granted` with the site grant, 404 or 400 for another tenant's host → `not_found`), the library among the site's drives by its `webUrl` (the URL segment is localized, e.g. `Freigegebene Dokumente`, and may differ from the name, e.g. `Plne` for `Pläne`), else a subsite among the site's subsites (`/sites/{id}/sites`) by its `webUrl`, in which the rest resolves the same way (neither → `not_found_or_not_granted` with the site grant), the folder by path in that drive (a file → `unsupported_url`). A missing folder is `not_found` only when the closest folder above it the app sees shows all of its children (SharePoint's `childCount` counts children the app is not granted); otherwise `not_found_or_not_granted` with the folder grant, since a site granted only in parts answers 404 for an existing folder too.
  - `SharePointListing` — lists through delta queries: a drive's root for a library, the folder for a folder (Graph lists it recursively), every document library of a site (`driveType` `documentLibrary`; lists and OneDrive are not synced), all pages (`@odata.nextLink`) into one result. Items are files only, with IDs `{drive-id}/{item-id}`, paths below the location (a site's prefixed with the library's name) built from the folders kept in the cursor, and as version the content hash (`quickXorHash`), since SharePoint gives an Office document a new `cTag` when it is renamed or moved. Deleted entries carry only an ID and whether they were a file or a folder; deleted files are passed on by ID, also when never listed. A full listing starts over when Graph demands it (`410`), a known folder was renamed, moved or deleted (Graph reports it without its files), or a site's libraries changed.
  - `SharePointSyncAdapter` — the `ConnectorSyncAdapter` for Microsoft 365. The first listing resolves the location's URL (unresolvable → `access_lost`) and lists everything; later ones go on from the cursor (`SharePointCursor`, `application/models/sharepoint-cursor.ts`: per drive its root, prefix, delta link and folders as `[parentId, name]`). Content is downloaded through the pre-authenticated URL Graph redirects to, without the token; a deleted file is `gone`, an encrypted Office document `unprocessable` (`encrypted`). A file Graph refuses (403) is `access_lost` only when the location no longer resolves; otherwise that file fails on its own (e.g. one flagged as malware), so it cannot stop the location. A token Entra refuses and a listing answered with 403 or 404 (also a deleted location folder) are `access_lost`; throttling is `throttled`.
- **`ConnectorSyncAccessService`** — `resolve(connectorId, orgId)`: the connector with its product's adapter, or `null` while the connector is gone, belongs to another organization, is not set up or its product has no adapter.

## Sync contract

The sync engine (`domain/knowledge-base-sync`) sees only these outcomes, never tokens or credentials:

- **Changes** — `{ outcome: 'changes', items, removedItemIds, cursor, fullListing }`: added and changed items (renames and moves included) and the IDs of deleted or moved-out items, which may include IDs never listed. The cursor is opaque and passed back next time (`null` the first time). `fullListing: true` means the items are everything below the location, e.g. after the provider demanded a resync; whatever is not listed is gone.
- **Content** — `{ outcome: 'content', content (a stream), size }`, or `gone` when the item no longer exists, or `unprocessable` with a `reason` the provider only knows once it read the item (e.g. `encrypted`).
- **`access_lost`** — the grant was revoked, or the connector is gone or not set up.
- **`throttled`** — `{ retryAt }`, for the back-off (AYC-1885).

## Use Cases

- **`ListConnectorsUseCase`** — Every available product with its status for the organization of the current user; a product without a connector is not set up
- **`GetMicrosoft365ConnectorUseCase`** — Status, tenant ID and client ID of the organization's Microsoft 365 connector (`Microsoft365ConnectorOverview`, never credentials)
- **`SaveMicrosoft365ConnectorUseCase`** — Sets up or changes the connection. With a client secret, it replaces setup and credentials (`{ clientSecret }` encrypted as one value). Without one, it changes the setup and keeps the stored secret; while the connector is not set up, that fails with `ConnectorCredentialsRequiredError` (`CONNECTOR_CREDENTIALS_REQUIRED`, 400). Then it tests the saved connection and returns the result with the overview. The secret is never logged.
- **`TestMicrosoft365ConnectionUseCase`** — Tests the organization's Microsoft 365 connection; `ConnectorNotSetUpError` (`CONNECTOR_NOT_SET_UP`, 404) while it is not set up
- **`ListConnectorChangesUseCase`** / **`FetchConnectorItemContentUseCase`** (exported) — The changes below a location since a cursor, and one item's content, with the organization's own connector access. Run without a user (sync jobs), so the organization comes with the command; `access_lost` whenever `ConnectorSyncAccessService` resolves nothing.
- **`FindSetUpConnectorUseCase`** (exported) — The ID of the current user's organization's set-up connector for a product, for referencing it; `ConnectorNotSetUpError` otherwise.
- **`ResolveSharePointLocationUseCase`** (exported) — Checks a pasted SharePoint URL through the current user's organization's Microsoft 365 connector before it is added as a location: `found` with `kind` (`site`, `library`, `folder`), `name` and `location` (SharePoint's own URL of it, to add), `not_granted` or `not_found_or_not_granted` with the `grant` (`scope` `site` or `folder`, `command`), `not_found`, or `unsupported_url` (not a site, library or folder URL of SharePoint Online). `CONNECTOR_NOT_SET_UP` (404) while not set up, `CONNECTOR_CONNECTION_FAILED` (422) while Entra rejects the credentials, `PROVIDER_UNAVAILABLE_REJECTED_MICROSOFT_GRAPH` while Graph throttles. No HTTP endpoint yet (AYC-1637).
- **`RemoveConnectionUseCase`** — Clears setup and credentials of a product's connector and keeps the connector; changes nothing while it is not set up

## Infrastructure

- **`LocalConnectorsRepository`** — TypeORM implementation backed by `connectors`. FK to `orgs` with cascade delete.
- **`EntraAppTokenService`** — `EntraAppTokenPort` over Entra's v2.0 token endpoint (`POST {login}/{tenantId}/oauth2/v2.0/token`, scope `https://graph.microsoft.com/.default` or SharePoint Online's app ID `00000003-0000-0ff1-ce00-000000000000/.default`, 15 s timeout). Reads `roles` from the token without verifying it: it comes straight from Entra over TLS and is only passed back to Microsoft. Classifies `AADSTS90002`/`900023` (tenant not found), `700016` (client not found), `7000215` (invalid secret, also a secret ID entered as the secret) and `7000222` (expired secret); any other 4xx is another rejection. Transport failures, timeouts, 5xx and 429 go through `wrapProviderFailure` (provider `microsoft_entra`). `MICROSOFT_LOGIN_URL` (`connectors.microsoftLoginOrigin`, default `https://login.microsoftonline.com`) only points the e2e backend at a stand-in.
- **`MicrosoftGraphClient`** — `MicrosoftGraphPort` over HTTPS (30 s per request, 10 min per download including its body). Refuses a link to another origin, so a stored delta link can never send the token elsewhere, and follows a download's redirect without it. Graph failures go through `wrapProviderFailure` (provider `microsoft_graph`). `MICROSOFT_GRAPH_URL` (`connectors.microsoftGraphOrigin`, default `https://graph.microsoft.com`) only points the e2e backend at a stand-in.
- **`ConnectorCredentialEncryptionService`** — AES-256-GCM under `CONNECTOR_ENCRYPTION_KEY` (64 hex characters), output `base64(iv + ciphertext + authTag)` like the MCP credentials. The key is required only while the flag is on: the environment validation rejects a boot with the flag on and no key, and rejects a malformed key either way. Without a key the service fails on use, not at startup.

## HTTP API

Controller: `ConnectorsController`, base path `/connectors`, tag `connectors`. Org admins only (`@Roles(ADMIN)`), scoped to the admin's organization. Every route answers 404 while the flag is off.

| Method | Path                             | Description                                                                                                                                                             |
| ------ | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/connectors`                    | Every available product with its status, never its setup or credentials                                                                                                 |
| GET    | `/connectors/microsoft-365`      | Status, tenant ID and client ID; never the client secret                                                                                                                |
| PUT    | `/connectors/microsoft-365`      | Set up or change: `tenantId`, `clientId` (GUIDs), optional `clientSecret` (omit to keep the stored one); returns the overview with `connectionTest`                     |
| POST   | `/connectors/microsoft-365/test` | Test the connection: `outcome`, `permissions` (`name`, `required`, `granted`), `otherGrantedPermissions`, `entraErrorCode`; 404 `CONNECTOR_NOT_SET_UP` while not set up |
| DELETE | `/connectors/microsoft-365`      | Remove the connection (204): deletes setup and credentials, keeps the connector                                                                                         |

## Consumers

- `domain/knowledge-base-sync`: synced knowledge base locations reference a connector by ID and sync through the exported use cases.
- Frontend: admin settings → **Connections** (`/admin-settings/connections`, "Members & Access" group) and its Microsoft 365 page (`/admin-settings/connections/microsoft-365`), which shows the connection test after saving and runs it again on request.
