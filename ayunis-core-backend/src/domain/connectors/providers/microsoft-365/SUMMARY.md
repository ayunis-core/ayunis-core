# Microsoft 365 Connector Provider

The Microsoft 365 provider of the connectors module (`domain/connectors`): the organization's own Entra app, Microsoft Graph and SharePoint. `Microsoft365ConnectorModule` imports `ConnectorsCoreModule` and `ConnectorsInternalModule` and registers `SharePointSyncAdapter` with the latter's `ConnectorSyncAdapterRegistry`; nothing outside this folder imports it except the connectors module's `ConnectorsModule`. Credential scope `org`: the admin enters tenant, client ID and client secret.

Behind the `connectorsEnabled` feature flag like the rest of the connectors module.

## Domain

- **Microsoft 365** (`domain/`) — the organization's own Entra app: setup `{ tenantId, clientId }` (GUIDs, `GUID_PATTERN`) and credentials `{ clientSecret }`. Client secret only; no certificates. `MICROSOFT_365_PERMISSIONS` lists the Microsoft Graph application permissions Ayunis uses: `Sites.Selected` (required), `Files.SelectedOperations.Selected` and `Lists.SelectedOperations.Selected` (optional). `Microsoft365ConnectionTestOutcome` is the result of a connection test: `connected` or the setup mistake that stops it (`tenant_not_found`, `client_not_found`, `client_secret_invalid`, `client_secret_expired`, `consent_missing`, `consent_on_wrong_api`, `required_permission_missing`, `rejected` for any other refusal, `microsoft_unavailable`), or `unexpected_error` when the test itself failed after a save.
- **SharePoint** (`domain/`) — `parseSharePointUrl`: a URL copied from SharePoint Online (`*.sharepoint.com`) as host, site path (`sites/…` or `teams/…`, `''` for the root site) and the decoded path below it (library, folders); library views (`…/Forms/AllItems.aspx`, also with the folder in `?id=`), site pages (`SitePages`, `_layouts`) and `/:f:/r/…` links are understood, sharing links (`/:f:/s/…`) are not, as they only resolve through `/shares`. `siteGrant` / `folderGrant`: the Microsoft Graph PowerShell command (`Connect-MgGraph -Scopes "Sites.FullControl.All"`, then `Invoke-MgGraphRequest -Method POST`) that grants the organization's app `read` on a site (`POST /sites/{host}:/{site-path}:/permissions`, `grantedToIdentities`; for a subsite its site collection, as `Sites.Selected` cannot be granted on a subsite) or on a folder (`POST /drives/{drive-id}/root:/{path}:/permissions`, `grantedToV2`, for `Files.SelectedOperations.Selected`); values are PowerShell literal strings. `isProtectedOfficeFile`: a Word, Excel or PowerPoint download (by its content type) that is a compound file, i.e. encrypted (a Purview sensitivity label with encryption).

## Ports

- **`MicrosoftGraphPort`** — Microsoft Graph v1.0 with an app-only token: `get(token, pathOrLink)` (a path below `/v1.0` or a link Graph returned) and `download(token, path)` (content, size, content type). Answers `ok`, `not_found`, `access_denied` (403), `resync_required` (410), `throttled` (`429`/`503` with `Retry-After`, as `retryAt`) or `rejected` (any other 4xx, with Graph's error code); throws a `ProviderUnavailableError` for transport failures, timeouts, 5xx and a 429 without `Retry-After`.
- **`EntraAppTokenPort`** — `requestToken(credentials, resource)`: an app-only token (client credentials flow) for Microsoft Graph or SharePoint, with the application permissions (`roles` claim) granted in it, or Entra's refusal (`EntraTokenRejection` plus its `AADSTS…` code). Throws a `ProviderUnavailableError` when Entra cannot be reached, times out or answers 5xx/429.

## Application Services

- **`Microsoft365AppTokenService`** — `requestToken(connector, resource)`: decrypts the connector's stored secret and requests an app-only token. Tokens and the secret stay inside the provider; SharePoint syncing reuses this service. `ConnectorNotSetUpError` while the connector has no credentials.
- **`Microsoft365ConnectionTestService`** — `test(connector)`: requests a Graph token and compares its roles with `MICROSOFT_365_PERMISSIONS`. A Graph token without roles is followed by a SharePoint token, which tells missing admin consent (`consent_missing`) from permissions added on the SharePoint API instead of Microsoft Graph (`consent_on_wrong_api`). Entra being unavailable is the outcome `microsoft_unavailable`; the failure is still reported to AppSignal (`reportUnexpectedError`). It does not read the app registration, which would need `Application.Read.All`. Returns `Microsoft365ConnectionTestResult`: outcome, the permissions Ayunis uses with whether each is granted, other granted Graph permissions, Entra's error code; never the token.
- **`Microsoft365GraphTokensService`** — Graph tokens for syncing, kept per connector until five minutes before they expire, so a sync asks Entra once rather than per file; changed setup or credentials get a new one. `withAccessToken(connector, work)` runs `work` with it, `null` while the connector is not set up or Entra rejects it; a token Graph refused (401) is dropped, for syncing and resolving alike.
- **SharePoint** (`services/sharepoint/`):
  - `SharePointLocationResolver` — resolves a parsed URL part by part, never through `/shares` (which answers 403 for granted-but-missing, not granted and non-existent alike): the site by path (403 → `not_granted` with the site grant, 404 or 400 for another tenant's host → `not_found`), the library among the site's drives by its `webUrl` (the URL segment is localized, e.g. `Freigegebene Dokumente`, and may differ from the name, e.g. `Plne` for `Pläne`), else a subsite among the site's subsites (`/sites/{id}/sites`) by its `webUrl`, in which the rest resolves the same way (neither → `not_found_or_not_granted` with the site grant), the folder by path in that drive (a file → `unsupported_url`). A missing folder is `not_found` only when the closest folder above it the app sees shows all of its children (SharePoint's `childCount` counts children the app is not granted); otherwise `not_found_or_not_granted` with the folder grant, since a site granted only in parts answers 404 for an existing folder too.
  - `SharePointListing` — lists through delta queries: a drive's root for a library, the folder for a folder (Graph lists it recursively), every document library of a site (`driveType` `documentLibrary`; lists and OneDrive are not synced), all pages (`@odata.nextLink`) into one result. Items are files only, with IDs `{drive-id}/{item-id}`, paths below the location (a site's prefixed with the library's name) built from the folders kept in the cursor, and as version the content hash (`quickXorHash`), since SharePoint gives an Office document a new `cTag` when it is renamed or moved. Deleted entries carry only an ID and whether they were a file or a folder; deleted files are passed on by ID, also when never listed. A full listing starts over when Graph demands it (`410`), a known folder was renamed, moved or deleted (Graph reports it without its files), or a site's libraries changed.
  - `SharePointSyncAdapter` — the `ConnectorSyncAdapter` for Microsoft 365. The first listing resolves the location's URL (unresolvable → `access_lost`) and lists everything; later ones go on from the cursor (`SharePointCursor`, `application/models/sharepoint-cursor.ts`: per drive its root, prefix, delta link and folders as `[parentId, name]`). Content is downloaded through the pre-authenticated URL Graph redirects to, without the token; a deleted file is `gone`, an encrypted Office document `unprocessable` (`encrypted`). A file Graph refuses (403) is `access_lost` only when the location no longer resolves; otherwise that file fails on its own (e.g. one flagged as malware), so it cannot stop the location. A token Entra refuses and a listing answered with 403 or 404 (also a deleted location folder) are `access_lost`; throttling is `throttled`.
  - `SharePointSyncAdapter.resolveLocation` (the provider contract's location check, called through `ResolveConnectorLocationUseCase`) — a pasted SharePoint URL: `found` with `kind` (`site`, `library`, `folder`), `name` and `location` (SharePoint's own URL of it, to add), `not_granted` or `not_found_or_not_granted` with the `grant` (`scope` `site` or `folder`, `command`), `not_found`, or `unsupported_url` (not a site, library or folder URL of SharePoint Online). `CONNECTOR_NOT_SET_UP` (404) while the setup is unreadable, `CONNECTOR_CONNECTION_FAILED` (422) while Entra rejects the credentials, `PROVIDER_UNAVAILABLE_REJECTED_MICROSOFT_GRAPH` while Graph throttles.

## Use Cases

- **`GetMicrosoft365ConnectorUseCase`** — Status, tenant ID and client ID of the organization's Microsoft 365 connector (`Microsoft365ConnectorOverview`, never credentials)
- **`SaveMicrosoft365ConnectorUseCase`** — Sets up or changes the connection. With a client secret, it replaces setup and credentials (`{ clientSecret }` encrypted as one value). Without one, it changes the setup and keeps the stored secret; while the connector is not set up, that fails with `ConnectorCredentialsRequiredError` (`CONNECTOR_CREDENTIALS_REQUIRED`, 400). Then it tests the saved connection and returns the result with the overview; as the connector is already stored then, a test that throws unexpectedly is logged, reported to AppSignal and returned as `unexpected_error` instead of failing the save. The secret is never logged.
- **`TestMicrosoft365ConnectionUseCase`** — Tests the organization's Microsoft 365 connection; `ConnectorNotSetUpError` (`CONNECTOR_NOT_SET_UP`, 404) while it is not set up

Removing the connection is the core's `RemoveConnectionUseCase`; resolving a location the core's `ResolveConnectorLocationUseCase`.

## Infrastructure

- **`EntraAppTokenService`** — `EntraAppTokenPort` over Entra's v2.0 token endpoint (`POST {login}/{tenantId}/oauth2/v2.0/token`, scope `https://graph.microsoft.com/.default` or SharePoint Online's app ID `00000003-0000-0ff1-ce00-000000000000/.default`, 15 s timeout). Reads `roles` from the token without verifying it: it comes straight from Entra over TLS and is only passed back to Microsoft. Classifies `AADSTS90002`/`900023` (tenant not found), `700016` (client not found), `7000215` (invalid secret, also a secret ID entered as the secret) and `7000222` (expired secret); any other 4xx is another rejection. Transport failures, timeouts, 5xx and 429 go through `wrapProviderFailure` (provider `microsoft_entra`). `MICROSOFT_LOGIN_URL` (`connectors.microsoftLoginOrigin`, default `https://login.microsoftonline.com`) only points the e2e backend at a stand-in.
- **`MicrosoftGraphClient`** — `MicrosoftGraphPort` over HTTPS (30 s per request, 10 min per download including its body). Refuses a link to another origin, so a stored delta link can never send the token elsewhere, and follows a download's redirect without it. Graph failures go through `wrapProviderFailure` (provider `microsoft_graph`). `MICROSOFT_GRAPH_URL` (`connectors.microsoftGraphOrigin`, default `https://graph.microsoft.com`) only points the e2e backend at a stand-in.

## HTTP API

Tag `connectors`; every route answers 404 while the flag is off. The operation IDs are those the routes had before they moved here (`ConnectorsController_*`), so the generated clients are unchanged.

`Microsoft365ConnectorController`, base path `/connectors/microsoft-365`, org admins only (`@Roles(ADMIN)`):

| Method | Path                             | Description                                                                                                                                                             |
| ------ | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/connectors/microsoft-365`      | Status, tenant ID and client ID; never the client secret                                                                                                                |
| PUT    | `/connectors/microsoft-365`      | Set up or change: `tenantId`, `clientId` (GUIDs), optional `clientSecret` (omit to keep the stored one); returns the overview with `connectionTest`                     |
| POST   | `/connectors/microsoft-365/test` | Test the connection: `outcome`, `permissions` (`name`, `required`, `granted`), `otherGrantedPermissions`, `entraErrorCode`; 404 `CONNECTOR_NOT_SET_UP` while not set up |
| DELETE | `/connectors/microsoft-365`      | Remove the connection (204): deletes setup and credentials, keeps the connector                                                                                         |

`SharePointLocationsController` (base path `/connectors/microsoft-365/sharepoint-locations`, every member of the organization, 404 while the flag is off): `POST /resolve` with `{ url }` checks a pasted SharePoint URL before it is added to a knowledge base and returns `outcome`, `kind`, `name`, `location` (to add) and `grant` (`scope`, `command`), `null` where they do not apply. Members may resolve because whoever may edit a knowledge base may add SharePoint to it, and IT decides what is reachable.

## Consumers

- Frontend: the knowledge base detail pages' synced sources card ("Add source → SharePoint") resolves URLs through `SharePointLocationsController`.
- Frontend: admin settings → Integrations → Microsoft 365 (`/admin-settings/integrations/microsoft-365`, `pages/admin-settings/microsoft-365-connector/`), which shows the connection test after saving and runs it again on request.
