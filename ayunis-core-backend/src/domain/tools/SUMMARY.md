# Extensible Tools

Pluggable tool system with JSON schema validation and execution.

Tools provide an extensible capability system where AI agents invoke typed actions—HTTP calls, code execution, chart generation, image generation, source queries, internet search, email, calendar, document editing/export preparation, spreadsheet creation and updates, and MCP operations—during conversations.

The tools module implements a polymorphic tool system with JSON schema-based parameter validation. The abstract `Tool` entity specializes into concrete types including `HttpTool`, `CodeExecutionTool`, `InternetSearchTool`, `WebsiteContentTool`, source and knowledge retrieval tools, email and calendar tools, chart tools, MCP tools, `ProductKnowledgeTool`, `ActivateSkillTool`, document tools, `CreateSpreadsheetTool`, `UpdateSpreadsheetTool`, and `GenerateImageTool`. `ToolBox` groups tools by type, while `ConfigurableTool` adds configuration data. Tool entities own schemas and validation only; frontend rendering and runtime continuation are selected independently by their respective adapters.

Each tool type has a dedicated handler for execution. Document tools manage versioned artifacts during conversations, including letterhead assignment and surgical search-and-replace edits. Spreadsheet tools create and fully replace spreadsheet artifacts from columns and rows, including text, numbers, and Excel formulas; their handlers serialize the grid through the artifacts module's spreadsheet content helpers and provide spreadsheet-specific recovery guidance for version conflicts. Email artifact tools create, read, and update versioned plain-text drafts; delivery remains an explicit user action through the artifacts module. `GenerateImageTool` accepts a prompt plus optional reference-image parameters (`reference_uploaded_image_ids` with `<messageId>:<index>` refs taken from the `[image ref: …]` labels the inference mapper injects next to every uploaded image, `reference_generated_image_ids` to iterate on earlier generations). `GenerateImageToolHandler` resolves the permitted image model, resolves requested reference images to raw bytes via the threads module's `DownloadReferenceImagesUseCase`, then enforces the image quota — references before quota, so a failed reference lookup (exposed to the model for a corrected retry) never consumes a quota slot — generates and stores the image, and reports usage when applicable.

The module includes tool assembly, runtime execution, embedding and text-extraction utilities, and validation helpers. `ExecuteToolUseCase` removes schema-disallowed explicit nulls before dispatching calls. Validation errors are formatted in plain language for model recovery instead of exposing raw AJV output (AYC-646). Most entities delegate validation to `validateToolParams`; `McpIntegrationTool` handles third-party schemas leniently, and `GenerateImageTool` uses the same formatted errors within its tool-execution error contract. `CreateCalendarEventTool.validateParams` adds date checks the JSON schema cannot express (`start`/`end` parseable as ISO 8601, `end` after `start`). Runtime tools that do not use a backend handler validate through the runtime's `validateInput` seam, so malformed widget input is fed back to the model instead of reaching the client (AYC-675).

The module integrates with **agents** for tool assignment, **runs** for runtime execution, **sources**, **rag**, and **knowledge-bases** for retrieval, **mcp** for protocol-bridged tools, **retrievers** for search and content tools, **artifacts** for document and spreadsheet persistence, **skill-templates** for skill activation, **models** for model resolution and image generation, **quotas** for fair-use enforcement, and **threads** for generated image storage and reference-image resolution.
