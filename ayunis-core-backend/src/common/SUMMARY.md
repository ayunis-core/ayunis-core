Shared Infrastructure
Cross-cutting utilities, clients, errors, middleware, and services shared across modules.

The common module provides foundational infrastructure used by all bounded contexts: email sending, token counting, PII anonymization, external API clients (code-execution, Locaboo, Presidio), request-scoped context, error handling, pagination, logging, guards, validators, middleware, database helpers, and the shared lazy-arming provider stream idle watchdog. The Presidio provider records payload length and total latency, while its client forwards the service's queue, model-load, processing, and cold-start timings as safe AppSignal log attributes without logging source text.

The common module is the shared kernel of the backend, imported globally or by individual domain and IAM modules. It contains no business logic but provides essential infrastructure services. Key subdirectories include `emails/` for SMTP-based email delivery, `token-counter/` for LLM token estimation via tiktoken or simple heuristics, `context/` for request-scoped user identity using `nestjs-cls`, and `errors/` for the base `ApplicationError` class and global exception filter. Additional capabilities include `anonymization/` for PII detection via Presidio, `email-templates/` for MJML-rendered transactional emails, `clients/` for external API integrations, `pagination/` for standardized paginated queries and responses, `logger/` for the logging boundary — `LoggingModule` owns the nestjs-pino configuration (development pretty output, production JSON/AppSignal transports) and `installNestLogger` installs it as Nest's logger during bootstrap, so application code only ever imports `Logger` from `@nestjs/common`, `puppeteer/` for the lazily launched shared headless-Chromium browser (`LazyChromiumBrowser`) used for PDF rendering, `middleware/` for cookie parsing and security headers, including runtime-configured basemap tile origins, `process/` for the global unhandled-rejection and uncaught-exception crash handlers, attached at import time before the application module graph loads, plus the helper that starts the continuous AppSignal `backend_process` heartbeat after successful application startup, `guards/` for the `@Public()` decorator bypassing JWT and the IP-keyed `RateLimitGuard` enforcing `@RateLimit()` (in `decorators/`) request throttling, bound globally via `APP_GUARD` in the IAM module, `validators/` for JSON schema validation, `filters/` for converting domain errors to HTTP responses with AppSignal error reporting, `db/` for the `BaseRecord` TypeORM superclass and the case-insensitive `exactEmail` query operator, `decorators/` for the `HandleUnexpectedErrors` decorator that centralizes logging and unexpected-error mapping for promise-based use cases, `http/` for shared presenter helpers such as document-upload interceptor setup, MIME validation, and temp-file cleanup, `streaming/` for stateful stream-lifecycle helpers such as `StreamIdleWatchdog`, Pino redaction prevents identity, content, URL, and request-secret fields from reaching outputs; its mixin adds CLS `user.id`/`org.id` and active OpenTelemetry `trace_id`/`span_id` attributes for AppSignal correlation. `testing/` provides `createLoggerMock`, which spies on `Logger.prototype` so specs can assert on the loggers providers construct themselves, and `events/` provides the `DeferredCleanupEvent` base class and `runDeferredCleanup` helper implementing the two-phase deletion-cleanup contract (listeners register irreversible external cleanup pre-delete via `deferCleanup`; the emitting use case runs the drained tasks only after the row delete succeeds, each error-swallowed).
