# Fynn Preview acceptance

Use this checklist for AYC-1239 and AYC-1364–1368. Engineering implementation and local regression tests are ready; provider acceptance is complete only after the evidence below is recorded against a real Preview webhook. Keep all PRs unmerged until the team reviews the results. Production activation belongs to REV-130/131.

## Before the session

- Use Fynn **Preview**, `https://preview.fynn.eu`, API `https://preview.coreapi.io`. Never change production customers during acceptance.
- Use local test organizations and keep real external sinks disabled or replaced by local mocks. Development has no separate StartDeliver test credentials; mock receipt proves event compatibility, not live StartDeliver acceptance.
- Keep the existing UI workspace running. Start the latest stack alongside it only on approved free ports. The older workspace alone does not prove that the new sync endpoint is running.
- Record the checked-out Core/Connect revisions, local Core API URL, frontend URL, Connect URL, and public Connect development URL. The Fynn target is `<public Connect URL>/webhooks/fynn`; expose Connect, not Core's internal API.
- Check each test customer's `ayunis-core-uuid`. Preview's `00000000-0000-4000-8000-0000000000NN` values are placeholders unless matching local organizations were deliberately created. Do not accidentally relink a production organization.

### Offline validation

From the Core repository:

```sh
node --test scripts/fynn-preview-readiness.test.mjs
cd ayunis-core-backend
pnpm test --runTestsByPath src/integrations/fynn/application/services/map-fynn-subscription.spec.ts src/integrations/fynn/application/use-cases/sync-fynn-subscription/sync-fynn-subscription.use-case.spec.ts src/integrations/fynn/application/use-cases/reconcile-fynn-subscriptions/reconcile-fynn-subscriptions.use-case.spec.ts --runInBand
pnpm run test:fynn-lifecycle
```

The database suite requires the local development database configuration; inject secrets from Infisical as usual. From the Connect checkout run `npm test`, `npm run typecheck`, and `npm run build`.

With both current services running, from the Core repository run this probe with their actual local ports:

```sh
infisical run --env=dev --path=/backend -- node scripts/fynn-preview-readiness.mjs --core-api-url http://localhost:CORE_PORT/api --connect-url http://localhost:CONNECT_PORT
```

The readiness probe never contacts Fynn. It checks local health, service authentication using an invalid UUID, and rejection of an invalid webhook signature. It refuses remote URLs and never prints credentials. A passing probe does **not** prove that Fynn can deliver a real webhook or that its secret matches.

## Real webhook setup

1. Create the Preview webhook after the public development URL is reachable. Choose API version **v1**.
2. Subscribe to available `subscription.*` events, `subscription_item.terminated`, `entitlement.state.updated`, and `customer.updated`. Product/coupon events are not needed.
3. Store the generated signing secret in Connect's Development configuration, then reload the owned Connect process.
4. Trigger a customer UUID update or a harmless Preview subscription change. Record Fynn's delivery ID, delivery HTTP result, Connect's forwarding result, Core's sync result, and the resulting Core state.
5. For phase/item events, capture the actual resource-ID structure. Subscription subresource IDs must not be mistaken for subscription IDs. Envelope billing values are never authoritative; Core reloads the API.

## Cross-cutting acceptance

- Create/change/cancel/revoke cancellation/pause/resume/terminate in Preview; verify state and history, including Academy.
- Replay a delivery; unchanged state creates no duplicate subscription or outgoing event. Deliver older triggers after newer ones; current API state wins.
- Verify a missed webhook is repaired by the daily job at **00:05 Europe/Berlin**, through the same sync path. Record the `fynn_reconciliation` check-in.
- Pending entitlements/API failure preserve the last committed state. A valid serving sibling remains usable while another provisions; unresolved provisioning with no serving candidate retries.
- Missing-link diagnostics: search `FYNN_ORG_LINK_MISSING` in Core logs. An intentionally removed UUID still revokes previously tracked paid/Academy access; repeated unlink delivery is harmless. Deleted customers follow the same safe cleanup rules.
- UUID moves revoke the old organization's synced access. Invalid UUIDs or multiple serving plans surface errors without silently assigning access.
- Free trials remain editable. Starting current paid access exhausts a Core trial; future-only paid access does not end it early. Ending paid access does not resurrect an exhausted trial.
- With Fynn management enabled, subscription and Academy edits are blocked in UI/API, subscription history stays visible, and full seat plans cannot auto-expand on invite. Toggle off restores manual behavior; self-hosted remains unaffected.
- Capture `subscription.created` and monthly-credit update delivery at the local sink, including stable retry IDs and correct values. Live StartDeliver receipt remains a separate acceptance item until a safe test destination is available.
- Check invalid signature and invalid service token rejection; provider keys, tokens, signing secrets and full billing payloads must not appear in diagnostic evidence.
