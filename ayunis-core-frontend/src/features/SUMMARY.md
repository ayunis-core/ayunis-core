# Cross-Cutting Logic

Self-contained business logic modules shared across multiple pages and widgets.

Feature modules and standalone hooks provide cross-cutting concerns: theme management (dark/light mode persistence), language switching (German/English via i18next), model/provider configuration with provider icon utilities, usage analytics data hooks for statistics, charts, and distribution metrics, skill action hooks for toggling skill active/pinned state, marketplace configuration for exposing marketplace availability and destination URLs, fair use limit editing for shared limit validation and edit state, permission gating for hiding UI controls the current user lacks access to, and active thread-run cancellation.

The `theme/` feature manages dark/light mode with localStorage persistence through `useTheme`, `setTheme`, and `getTheme` utilities. The `language/` feature wraps i18next language switching in a `useLanguage` hook. The `models/` feature provides `useLanguageModels`, `useEmbeddingModels`, `useImageGenerationModels`, and `useProviders` hooks for fetching AI model configurations by type, plus provider constants and icon utilities for Ollama, Mistral, Anthropic, and OpenAI. The `usage/` feature contains analytics hooks (`useUsageStats`, `useUserUsage`, `useProviderUsage`, `useProviderUsageChart`, `useModelDistribution`, `useUsageConfig`) powering admin dashboard charts. The `skill-actions/` feature provides `useToggleSkillActive` and `useToggleSkillPinned` hooks for toggling skill active and pinned state. The `marketplace/` feature provides a `useMarketplaceConfig` hook that returns marketplace availability plus the configured destination URL for marketplace entry points. The `fair-use-limit-editor/` feature provides `useFairUseLimitEditor` for reusable fair use limit edit state and validation. The `academy/` feature exposes the academy add-on gate (`isAcademyAddonActive`, `useIsAcademyAddonActive`), `useDownloadCertificate` for downloading the KI-Führerschein certificate PDF (used by the quiz result card and the academy overview completion banner), `useAcademyAccessStatus` for the org-level certificate requirement that gates Core chat (the notice explaining the gate lives in `widgets/academy-gate-notice`), and `useAcademyProgress` for per-chapter pass state and the whole-academy completion date — shared by the academy overview and the account-settings certificate card, and add-on gated server-side, so callers outside the academy pass `enabled: false` while the add-on is inactive. For orgs on annual renewal it also owns the pre-expiry warnings: the pure `resolveCertificateExpiryNotice` maps days-until-expiry to a notice level (dismissible pop-up at 30 days, red pop-up at 14, non-dismissible countdown banner in the final 7); the components that render those notices live in `widgets/certificate-expiry`, so this feature stays hooks and pure logic. The `permissions/` feature centralizes frontend authorization through the pure `createAuthorization(role, permissions)` helper and its React adapter `useAuthorization` (`lib/`, `api/`), exposing `can`, `canAny`, and `hasRole` without conflating delegatable permissions with admin-only role policy. `useMyPermissions` fetches the current user's effective RBAC permissions from `GET /permissions/me` for gating UI controls — e.g. hiding the create-skill / create-knowledge-base controls from members who lack the permission; the `PermissionGate` component (`ui/`) renders its children only for holders of any of the given permissions; and `allowedSettingsSections(authorization)` with the `MANAGER_SETTINGS_SECTIONS` map (`lib/`) is the single answer to "may this user open this admin-settings section?" used by the `admin-settings` route guard and both sidebars (admins get the settings root, which prefixes every section, while other roles get only permission-backed sections). The `thread-run/` feature owns thread deletion and the browser-local active-run registry. Starting a streamed send registers its `AbortController`; deleting that thread from either the chat header or sidebar aborts the stream before issuing the delete request. Standalone hooks at the feature root include `useAgents` for agent listing, `useRenameThread` for thread management, `useAutoScroll` for chat scrolling behavior, `useContentScrollHeader` for tracking whether scrolled content sits under the frosted overlay header, `useChatsSidebarOpen` for persisting chats sidebar collapsed state, `useKeyboardShortcut` for hotkey bindings, `usePermittedModels` for org-scoped model access, `useReleaseNotes` for changelog display, `useRedirectNotification` for post-navigation toasts, and `useGtm` for Google Tag Manager integration. The `workspaces/` feature holds only the workspace ("Projekt") hooks that are genuinely shared across slices — `useWorkspaces` (disabled while the feature flag is off so the gated controller's 404 never surfaces as an error) and `useDeleteWorkspace` — plus the `Workspace` type in `model/`; single-consumer mutation hooks live in their consumer widget's `api/` segment instead (`useCreateWorkspace`, `useUpdateWorkspace` in the dialog widgets). The `favorites/` feature provides the shared pinning hooks, `useFavorites` and `useToggleFavorite`, used by the sidebar, the chat header, and the workspace pages; favorites form a strict, user-specific ordered list, and reordering is submitted by the sidebar's own `useReorderFavorites` hook in `widgets/app-sidebar/api/`. The `chat-initiation/` feature owns `useInitiateChat`, the full new-chat pipeline (create the thread — optionally filed under a workspace — upload sources, attach knowledge bases and integrations, stage the pending message, navigate to the created chat), shared by the new-chat page and the workspace page's embedded composer; the new-chat settle animation is opt-out via its `settleAnimation` option. `feature-toggles/` gained `useIsWorkspacesEnabled`.
