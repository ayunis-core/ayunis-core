# Cross-Cutting Logic

Self-contained business logic modules shared across multiple pages and widgets.

Feature modules and standalone hooks provide cross-cutting concerns: theme management (dark/light mode persistence), language switching (German/English via i18next), model/provider configuration with provider icon utilities, usage analytics data hooks for statistics, charts, and distribution metrics, skill action hooks for toggling skill active/pinned state, marketplace configuration for exposing marketplace availability and destination URLs, fair use limit editing for shared limit validation and edit state, permission gating for hiding UI controls the current user lacks access to, super-admin user mutations, and active thread-run cancellation.

The `super-admin-user-actions/` feature centralizes password-reset and deletion mutations, including cache invalidation and error handling, for super-admin user tables.

The `bulk-user-invite/` feature provides the shared CSV upload, preview, and invitation result flow used by organization Admins and Super Admins. Its optional `teams` column accepts pipe-separated team names and routes the request through the role-appropriate bulk invite endpoint.

The `sso/` feature owns generated-client discovery and account-linking hooks, browser navigation to backend SSO endpoints, tab-scoped memory of the last successful SSO organization for returning sign-in, and conversion of stable, non-secret callback error codes into user-facing categories.

The `anonymous-mode-default/` feature provides `useAnonymousModeDefault`, the org-wide default for starting new chats in anonymous mode. The admin anonymization settings page sets it, and the new-chat page and the workspace chat starter use it to prefill their anonymous toggle; users can still turn it off per chat, and a model's `anonymousOnly` enforcement keeps precedence. The value is persisted per organization through chat settings. Route loaders await the member-readable default before the composers initialize; saves invalidate both admin settings and member-default queries.

The `theme/` feature manages dark/light mode with localStorage persistence through `useTheme`, `setTheme`, and `getTheme` utilities. The `language/` feature wraps i18next language switching in a `useLanguage` hook. The `models/` feature provides `useLanguageModels`, `useEmbeddingModels`, `useImageGenerationModels`, and `useProviders` hooks for fetching AI model configurations by type, plus provider constants and icon utilities for Ollama, Mistral, Anthropic, and OpenAI. The `usage/` feature contains analytics hooks (`useUsageStats`, `useUserUsage`, `useProviderUsage`, `useProviderUsageChart`, `useModelDistribution`, `useUsageConfig`) powering admin dashboard charts. The `skill-actions/` feature provides `useSetSkillActivation` and `useSetSkillPin` hooks for idempotently setting personal skill activation and pin state, plus `useImproveSkillText`, which asks Ayunis Core to rewrite a skill's trigger or instructions and maps the improver's error codes (empty answer, no usable model, usage limit reached) to toasts. The `marketplace/` feature provides a `useMarketplaceConfig` hook that returns marketplace availability plus the configured destination URL for marketplace entry points. The `fair-use-limit-editor/` feature provides `useFairUseLimitEditor` for reusable fair use limit edit state and validation. The `academy/` feature exposes the add-on gate, the org-level Academy completion status that gates Core chat, per-chapter confirmation and whole-academy progress, and `useDownloadParticipationConfirmation` for the KI-Schulung nach EU AI Act participation-confirmation PDF. For annual renewal it also owns the pure expiry-notice calculation; rendering remains in the expiry widgets. The `permissions/` feature centralizes frontend authorization through the pure `createAuthorization(role, permissions)` helper and its React adapter `useAuthorization` (`lib/`, `api/`), exposing `can`, `canAny`, and `hasRole` without conflating delegatable permissions with admin-only role policy. `useMyPermissions` fetches the current user's effective RBAC permissions from `GET /permissions/me` for gating UI controls — e.g. hiding the create-skill / create-knowledge-base controls from members who lack the permission; the `PermissionGate` component (`ui/`) renders its children only for holders of any of the given permissions; and `allowedSettingsSections(authorization)` with the `MANAGER_SETTINGS_SECTIONS` map (`lib/`) is the single answer to "may this user open this admin-settings section?" used by the `admin-settings` route guard and both sidebars (admins get the settings root, which prefixes every section, while other roles get only permission-backed sections). The `thread-run/` feature owns thread deletion and the browser-local active-run registry. Starting a streamed send registers its `AbortController`; deleting that thread from either the chat header or sidebar aborts the stream before issuing the delete request, then clears its local prompt draft after deletion succeeds. Standalone hooks at the feature root include `useAgents` for agent listing, `useRenameThread` for thread management, `useAutoScroll` for chat scrolling behavior, `useContentScrollHeader` for tracking whether scrolled content sits under the frosted overlay header, `useSidebarGroupOpen` for persisting a sidebar group's collapsed state in localStorage under a caller-supplied key (favorites and chats each pass their own), `useKeyboardShortcut` for hotkey bindings, `usePermittedModels` for org-scoped model access, `useReleaseNotes` for changelog display, `useRedirectNotification` for post-navigation toasts, and `useGtm` for Google Tag Manager integration. The `workspaces/` feature holds only the workspace ("Projekt") hooks that are genuinely shared across slices — `useWorkspace` for loading one workspace by id, `useWorkspaces` for listing workspaces, and `useDeleteWorkspace` — plus the `Workspace` type and the `WORKSPACES_PER_PAGE` page size in `model/`, shared by the overview route and the getting-started tour helper `findPinTourWorkspace` in `widgets/onboarding` so both agree on which rows are on page one; single-consumer mutation hooks live in their consumer widget's `api/` segment instead (`useCreateWorkspace`, `useUpdateWorkspace` in the dialog widgets). The `favorites/` feature provides the shared pinning hooks, `useFavorites` and `useToggleFavorite`, used by the sidebar, the chat header, and the workspace pages; favorites form a strict, user-specific ordered list, and reordering is submitted by the sidebar's own `useReorderFavorites` hook in `widgets/app-sidebar/api/`. The `chat-initiation/` feature owns `useInitiateChat`, the full new-chat pipeline (create the thread — optionally filed under a workspace — upload sources, attach knowledge bases and integrations, stage the pending message, navigate to the created chat), shared by the new-chat page and the workspace page's embedded composer; the new-chat settle animation is opt-out via its `settleAnimation` option.
