# Route Modules

Page components composing widgets and features for each application route.

Route-level page modules handle authentication, chat conversations, agent management, prompt libraries, knowledge base management, skill management, user settings, organization admin settings, and super-admin platform management. Each page follows a consistent internal structure with api/, ui/, and model/ subdirectories separating data hooks, components, and types.

The `auth/` group contains the login, register, email confirmation, password forgot/reset, and invite acceptance flows. The `chat/` and `new-chat/` pages manage AI conversation interfaces with message streaming, agent selection, knowledge base attachment (`useKnowledgeBaseAttachment` hook for adding/removing KBs on existing threads, plus pending-KB context state for new threads), and side-panel artifact editing flows such as changing an artifact's assigned letterhead. The chat run timeline displays accumulated raw tool input while it streams, renders malformed terminal calls as non-actionable errors, and retains those presentation-only errors across same-thread refetches without treating them as persisted history. The `chats/` page lists conversation threads. The `agents/` and `agent/` pages handle AI assistant browsing and detailed configuration. The `prompts/` page provides prompt library management. The `knowledge-bases/` page lists knowledge bases with creation and deletion, while `knowledge-base/` provides the detail view for a single knowledge base including document upload, removal, and property editing. The `skills/` page lists available skills, and `skill/` shows skill details. The academy learning content spans three page slices, one per route: `academy/` lists chapters (`AcademyPage`), `academy-chapter/` shows a single chapter with an embedded Loom video (`ChapterDetailPage`, using the `toLoomEmbedUrl` helper in `lib/` to rewrite Loom share URLs into embeddable iframe URLs), and `academy-chapter-quiz/` runs the chapter quiz (`ChapterQuizPage`); once the whole academy is completed, both the quiz's `QuizResultCard` and the completion banner on `AcademyPage` offer the KI-Führerschein certificate PDF download via the shared `useDownloadCertificate` hook from `features/academy`. The `install/` page handles app installation flows. User `settings/` includes account, general preferences, `chat-settings/` for per-user AI conversation configuration (custom system prompts), and per-user MCP credentials. The `admin-settings/` group covers organization administration: model configuration, MCP integrations (including a custom-server field builder for organization and user HTTP headers), team/user management, role & permission management (`roles-settings/` — a matrix where admins grant per-permission access to the MANAGER and USER roles; admins implicitly hold all), security, letterhead management (list in `letterheads-settings/`, detail/edit in `letterhead-detail/`), and usage analytics. The `super-admin-settings/` group provides platform-wide management for the models catalog, organization oversight, and platform configuration including per-tier fair-use message budgets via `FairUseLimitsSection` (with `useFairUseLimits` and `useSetFairUseLimit` hooks performing `windowMs ↔ windowHours` conversion at the hook boundary). Each page uses the hooks pattern—one custom hook per operation (create, update, delete)—encapsulating TanStack Query mutations with toast notifications and cache invalidation. The `workspaces/` page slice renders the `/workspaces` list — one row per workspace, with client-side search and sorting by last updated / created / alphabetical with locale-aware collation (pure functions in `lib/sortWorkspaces.ts`, unit tested) — plus the create dialog trigger and per-workspace pin buttons. The `workspace/` page slice renders `/workspaces/$workspaceId`: breadcrumb, hero with the workspace's icon and description, pin and settings actions, and the "Ihre Chats" tab whose count badge uses the server's pagination total rather than the loaded page size. Both routes redirect to `/chat` while the workspaces feature flag is off.
