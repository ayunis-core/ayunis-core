# Route Modules

Page components composing widgets and features for each application route.

Route-level page modules handle authentication, chat conversations, agent management, prompt libraries, knowledge base management, skill management, user settings, organization admin settings, and super-admin platform management. Each page follows a consistent internal structure with api/, ui/, and model/ subdirectories separating data hooks, components, and types.

The workspace page also includes the Erstellte Inhalte tab for project artifacts. Artifact rows open the corresponding chat editor through URL search parameters, while artifact lists load within the workspace tabs.

The `workspace/` page slice also includes context tabs for Wissen, Skills and Anweisungen. Its route loader fetches workspace context and attachable skill/knowledge-base candidates, while `api/useWorkspaceContextActions.ts` owns context mutations and invalidates the workspace context queries after changes.

The `super-admin-settings/users/` page provides a searchable cross-organization user directory with account lock status, account recovery, password reset, organization navigation, deletion, and CSV export controls. Organization admins see the same lock status and recovery action in their user settings.

Municipal SSO uses separate auth route slices for direct organization links, successful completion, and actionable failures. Every broker callback lands on one of these fixed application routes. SSO connections are managed by Superadmins rather than organization admins from Account Settings.

The Superadmin organization SSO tab configures one or more verified email domains for the same broker mapping and reviews the complete set before activation.

The `auth/` group contains the login, register, email confirmation, password forgot/reset, and invite acceptance flows. The `chat/` and `new-chat/` pages manage AI conversation interfaces with message streaming, agent selection, knowledge base attachment (`useKnowledgeBaseAttachment` hook for adding/removing KBs on existing threads, plus pending-KB context state for new threads), and side-panel artifact editing flows such as changing an artifact's assigned letterhead. The chat run timeline displays accumulated raw tool input while it streams, renders malformed terminal calls as non-actionable errors, and retains those presentation-only errors across same-thread refetches without treating them as persisted history. Its page-local `GeoJsonMapWidget` uses MapLibre to render point, line, polygon, and multi-geometries, fit their bounds, expose properties as plain-text popups, and show basemap plus distinct data attribution without duplication; runtime frontend configuration can override the basemap tiles and attribution. The `chats/` page lists conversation threads. The `agents/` and `agent/` pages handle AI assistant browsing and detailed configuration. The `prompts/` page provides prompt library management. The `knowledge-bases/` page lists knowledge bases with creation and deletion, while `knowledge-base/` provides the detail view for a single knowledge base including document upload, removal, and property editing. The `skills/` page lists available skills, and `skill/` shows skill details. The academy learning content spans three page slices, one per route: `academy/` lists chapters (`AcademyPage`), `academy-chapter/` shows a single chapter with an embedded Loom video (`ChapterDetailPage`, using the `toLoomEmbedUrl` helper in `lib/` to rewrite Loom share URLs into embeddable iframe URLs), and `academy-chapter-quiz/` runs the chapter quiz (`ChapterQuizPage`); once the whole academy is completed, both the quiz's `QuizResultCard` and the completion banner on `AcademyPage` offer the KI-Führerschein certificate PDF download via the shared `useDownloadCertificate` hook from `features/academy`. The `install/` page handles app installation flows. User `settings/` includes account, general preferences, `chat-settings/` for per-user AI conversation configuration (custom system prompts), and per-user MCP credentials. The `admin-settings/` group covers organization administration: model configuration, MCP integrations (including a custom-server field builder for organization and user HTTP headers), team/user management, role & permission management (`roles-settings/` — a matrix where admins grant per-permission access to the MANAGER and USER roles; admins implicitly hold all), security, letterhead management (list in `letterheads-settings/`, detail/edit in `letterhead-detail/`), and usage analytics. The `super-admin-settings/` group provides platform-wide management for the models catalog, organization oversight, and platform configuration including per-tier fair-use message budgets via `FairUseLimitsSection` (with `useFairUseLimits` and `useSetFairUseLimit` hooks performing `windowMs ↔ windowHours` conversion at the hook boundary). Each page uses the hooks pattern—one custom hook per operation (create, update, delete)—encapsulating TanStack Query mutations with toast notifications and cache invalidation. The `workspaces/` page slice renders the `/workspaces` list — one row per workspace, with client-side search and sorting by last updated / created / alphabetical with locale-aware collation (pure functions in `lib/sortWorkspaces.ts`, unit tested) — plus the create dialog trigger and per-workspace pin buttons. The `workspace/` page slice renders `/workspaces/$workspaceId`: breadcrumb, hero with the workspace's icon and description, pin and settings actions, and the "Ihre Chats" tab whose count badge uses the server's pagination total rather than the loaded page size. Both routes redirect to `/chat` while the workspaces feature flag is off. The `new-chat/` page gained `ui/WorkspacePicker.tsx`, a dropdown under the composer that files the new chat under a workspace (with inline workspace creation; re-selecting the current one detaches it) — the chosen id flows through `useInitiateChat` into thread creation, and the `/chat` route accepts a `workspaceId` search param to preselect it. The `workspace/` overview page gained `ui/WorkspaceChatStarter.tsx`, the full `ChatInput` composer wired to `features/chat-initiation` with the workspace fixed — sending lands directly in the created chat. `chat/` shows a pin star in the chat header when workspaces are enabled.
